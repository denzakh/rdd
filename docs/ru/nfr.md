# Нефункциональные требования (NFR / SLO)

**Назначение:** свести количественные характеристики системы в одном месте. Документ
показывает, _по каким числам_ судить о системе, а не только «работает / не работает».

> **Контекст демо-версии.** Проект — демонстрация архитектуры, а не клинический
> продакшен (см. «Границы демо-проекта» в [architecture-overview.md](./architecture-overview.md)).
> Поэтому каждая метрика разделена на две колонки: что гарантируется сейчас (демо,
> развёрнуто на Cloudflare) и целевые значения прод-версии клинического регистра.

---

## 1. Availability

| Уровень                 | Демо (сейчас)                                                                                        | Прод-версия                                                                         |
| ----------------------- | ---------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| Availability приложения | Не гарантируется SLA (best effort: развёртывание на Cloudflare Pages/Workers с платформенным uptime) | ≥ 99,5 % в месяц (≈ 3,6 ч недоступности/мес); SLO по ошибкам 5xx — < 0,5 % запросов |
| Плановые окна простоя   | Не планируются, деплой атомарный (Workers)                                                           | Вне рабочего времени клиник; rolling-деплой без окна                                |
| Деградация чтения       | Не реализована                                                                                       | При недоступности БД — только чтение из кэша/реплики, запись в offline-очередь      |

Демо-версия **не даёт гарантий доступности**: единственный инстанс D1 + ручной деплой.
Платформа Cloudflare сама по себе highly available, но SLA в проекте не измеряется
(нет uptime-мониторинга и alerting — вынесено за рамки демо).

## 2. RTO / RPO (disaster recovery)

| Метрика                      | Демо (сейчас)                                                                                                                                                                                                 | Прод-версия                                                                     |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| RTO (восстановление сервиса) | Не гарантируется; реальный путь — повторный деплой из Git (`npm run deploy`)                                                                                                                                  | ≤ 4 ч (пере-деплой из чистого репозитория + миграции)                           |
| RPO (потеря данных)          | Не гарантируется. Для D1 настроены только ручные миграции; регулярных бэкапов, point-in-time recovery и плана восстановления нет (см. «Backup / DR» в [architecture-overview.md](./architecture-overview.md)) | RPO ≤ 1 ч (регулярные бэкапы D1 / PITR), восстановление по проверяемому runbook |
| Проверяемость                | —                                                                                                                                                                                                             | Quarterly DR-учения: восстановление БД из бэкапа в staging                      |

## 3. Производительность

### 3.1. Фронтенд (виджет «Матрица»)

Источники: [matrix.md §2, §5.1](./matrix.md).

| Метрика                   | Порог                                                    | Как проверяется                                                                                                                                                                    |
| ------------------------- | -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Первый рендер грида       | ≤ 300 мс на референсном датасете                         | React Profiler / Chrome Performance                                                                                                                                                |
| Ререндер при вводе ячейки | Ровно 1 ячейка; строка и соседние строки не ререндерятся | Сейчас — unit-тесты селекторов zustand (`tests/unit/matrix-store.test.ts`); render-счётчики на референсном датасете (230 строк × 10 колонок) — целевое, в демо не автоматизированы |
| Скролл грида              | Без dropped frames (60 fps)                              | Chrome Performance                                                                                                                                                                 |
| Дебаунс ввода / персиста  | 300 мс (батч dirty-ячеек)                                | unit-тесты matrix-store (fake timers)                                                                                                                                              |

### 3.2. Сеть и пейджинг

| Метрика                            | Порог                                                                           | Обоснование                                                                                                     |
| ---------------------------------- | ------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Загрузка страницы списка пациентов | ≤ 1 с TTI на референсном датасете (пейджинг 20–50 записей, серверный рендеринг) | Next.js App Router, данные из D1 в одном регионе                                                                |
| Синхронизация коллаборации         | **Не реализована** (v1: чужие правки выявляются только при записи — CAS → 409)  | Проектное решение — polling 30–60 с ([matrix.md §6.3, §6.7](./matrix.md)); потеря данных невозможна за счёт CAS |

### 3.3. Безопасность и серверные действия

Источники: [auth.md §6](./auth.md), [spec-stage-3.md](./spec-stage-3.md).

| Метрика                                   | Порог                                                                                                                                                                                   | Назначение       |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------- |
| Задержка ответа при логине (успех/ошибка) | Постоянные ~400 мс, одинаковые для существующего/несуществующего email                                                                                                                  | Anti-enumeration |
| Блокировка после неверных паролей         | Вход: 5 попыток → 15 мин (этап 3, [spec-stage-3.md §3](./spec-stage-3.md)); смена пароля по ошибочному текущему паролю не блокируется; порог эскалации — WAF ([auth.md §12](./auth.md)) | Rate-limit       |
| TTL сессии                                | 12 ч, sliding renewal                                                                                                                                                                   | Аутентификация   |

### 3.4. Масштаб / ёмкость (демо-референсы)

| Метрика                            | Значение v1                                                 | Порог пересмотра                                                               |
| ---------------------------------- | ----------------------------------------------------------- | ------------------------------------------------------------------------------ |
| Бинарные клинические флаги в схеме | ~50 плоских колонок INTEGER 0/1                             | >100–150 флагов или атрибуты у признака → гибрид ([rdd-v1.md §7](./rdd-v1.md)) |
| Виртуализация матрицы              | Произвольное число строк (строки за viewport не рендерятся) | —                                                                              |
| Сборка                             | Lighthouse/размер бандла не регламентируются в демо         | Прод: бюджет per-route (например, LCP ≤ 2,5 с, CLS < 0,1)                      |

## 4. Мониторинг и алертинг

Демо: отсутствует (вынесено за рамки). Прод-версия обязана добавить:
uptime-пробники (Cloudflare Health Checks), alerting по ошибкам 5xx и p95-латентности
Server Actions, счётчики D1-латентности и `conflict_resolved` из `audit_log` (фоновый
уровень как базу для порогов эскалации).
