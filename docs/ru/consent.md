# Спека: согласие пациента — дата и версия формы ИС (./consent.md)

**Статус:** решение зафиксировано · **Зависимости:** реестр и карточка пациента (`spec-stage-2.md` §2, §4)
**Слой FSD:** `src/entities/patient/api/patient-repo.ts`, `src/features/patients/*`, `app/patients/*`

---

## 1. Решение (принято)

- **Дата согласия ставится автоматически при создании карточки**: `patients.consent_date` = дата создания (ISO-день). Включение пациента в исследование и фиксация даты согласия — один акт (`savePatientAction` → `createPatientRepository().create()`).
- **Версия формы ИС по умолчанию — `1`** (`CONSENT_CURRENT_VERSION`). Она выводится **текстовым полем на странице регистрации пациента** и доступна для правки при редактировании карточки: врач увеличивает версию при новой редакции текста согласия.
- **Отзыв согласия остаётся отдельным действием** (`patients.consent_withdrawn_at`, кнопка на карточке): данные физически не удаляются, пациент исключается из отчётов/экспорта (`entities/phase/api/queries.ts`, `entities/patient/api/patient-queries.ts`).
- **В статистическую выгрузку поля согласия не входят**: `consent_version`, `consent_date`, `consent_withdrawn_at` отсутствуют в `getDeidentifiedDataset` (фильтр «отозван → исключён из выборки» при этом действует). Метка редакции ИС нужна для сверки с этическим комитетом, а не биостатистику.
- **Реестр редакций текста ИС ведётся вне системы** (решение ЭК): в системе хранится только номер версии. Текст согласия в системе не хранится (ни в D1, ни в объектном хранилище).

### 1.2 Состояния согласия на карточке

| Состояние             | Условие                                                        | Кнопка                   |
| --------------------- | -------------------------------------------------------------- | ------------------------ |
| подписано             | `consent_version IS NOT NULL AND consent_withdrawn_at IS NULL` | «Отозвать согласие»      |
| отозвано              | `consent_withdrawn_at IS NOT NULL`                             | «Подписать согласие»     |
| не подписано (легаси) | обе колонки `NULL`                                             | «Зафиксировать согласие» |

Состояние «не подписано» возможно только у записей, созданных до этого решения (или заведённых напрямую через репозиторий/seed) — новые карточки его не получают. Отозвать незафиксированное согласие **нельзя**: иначе пациент выпал бы из отчётов без основания.

## 2. Что сознательно НЕ делаем

- нет справочника версий согласия (`consent_versions`), `consent_version` — `TEXT` без FK;
- нет текста ИС в системе;
- нет электронной подписи, DPA и иных юридически значимых механизмов (границы демо — `architecture-overview.md`, раздел «Границы демо-проекта»);
- нет отдельной таблицы истории подписей (частично покрывается `audit_log`: обновление карточки пишет `old_value`/`new_value` целиком, включая версию);
- нет метки согласия в статистической выгрузке.

## 3. Варианты эскалации (триггер → действие)

| Триггер                                                                                  | Что делать                                                                                                                                                                                                                                                      | Цена                                                                                                                     |
| ---------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Опечатка/расхождение версии: подписан неверный номер, «забыли увеличить версию»          | справочник `consent_versions(version TEXT PRIMARY KEY, effective_at, note, approved_by)` + валидация версии в `signConsent` + guard-тест «`CONSENT_CURRENT_VERSION` == последняя версия справочника»; по образцу `registry_versions` (`schema-evolution.md` §4) | ручная миграция `000N_consent_versions.sql` (+ `MANUAL_MIGRATIONS` в `scripts/db-restart.ts`), правки репозитория, тесты |
| Нужно показать врачу (или пациенту) текст подписанной редакции                           | текст редакции в справочнике в D1 (TEXT/Markdown, редакция неизменяема: правка текста = новая версия) + показ в `ConsentPanel`, страница `/admin/consent-versions`                                                                                              | справочник + UI + i18n                                                                                                   |
| Нужен юридически значимый первоисточник (скан/PDF с подписью)                            | скан в R2 (`MY_BUCKET` объявлен в `wrangler.jsonc`, кодом не используется) + авторизованное скачивание, ссылка из справочника версий                                                                                                                            | отдельный контур контроля доступа; выходит за заявленные границы демо                                                    |
| Нужна полная история подписей (кто, когда, какую редакцию; повторные подписания, отзывы) | таблица подписей `patient_consents(patient_id, version, signed_at, withdrawn_at, actor_id)` + запись в неё из `signConsentAction`/`withdrawConsentAction`                                                                                                       | миграция + правки репозитория и экшенов                                                                                  |
| Внешнее требование включить метку ИС в выгрузку                                          | вернуть `consent_version` в `getDeidentifiedDataset` (columns/meta) по образцу `registry_version` и **осознанно** переписать guard-тест `tests/unit/export-no-consent.test.ts`                                                                                  | ~10 строк                                                                                                                |
| Требуется «не подписанных» исключать из отчётов                                          | добавить `consent_version IS NOT NULL` в `CONSENT_OK` (`entities/patient/api/patient-queries.ts`) и в фазовые запросы; учитывать, что легаси-записи без версии выпадут из статистики                                                                            | несколько SQL + тесты                                                                                                    |

Порог эскалации — **внешнее требование** (этический комитет, регулятор, аудит), а не «на всякий случай»: каждое усложнение (справочник, текст, подписанный скан) добавляет контур сопровождения и обязательств.
